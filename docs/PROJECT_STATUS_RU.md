# TabTome: состояние проекта

Дата: 20 сентября 2026 года. Публичные версии расширения Firefox и Chrome — **0.12.1**; они доступны в Firefox Add-ons и Chrome Web Store. Версия приложения для Windows — **0.12.0**, версия Native Messaging protocol — **3**.

Система отправляет на Kindle или PocketBook одну или несколько уже открытых вкладок браузера либо вставленный форматированный фрагмент. Firefox- и Chrome-версии работают через короткоживущий локальный Node.js-компонент; Windows-установщик регистрирует Native Messaging для Firefox, Google Chrome и Chromium. Постоянного HTTP-сервера, облачного backend и автозапуска Windows нет.

## Реализовано

- Native Messaging вместо localhost и фонового сервера;
- защита от повторной SMTP-отправки через `jobId` и журнал состояний;
- извлечение одной или нескольких вкладок и частичная отправка при ошибке отдельной вкладки;
- вставка обычного и форматированного текста с временным session-only черновиком;
- сохранение абзацев, заголовков, выделения, списков, цитат, кода, ссылок, таблиц и изображений;
- сохранение EPUB на диск без SMTP либо одновременная отправка и сохранение локальной копии; папка по умолчанию — `Загрузки\\TabTome`;
- исправление неполного извлечения сложных статей и изображений на `novayagazeta.eu`, включая выбор более полного блока статьи и `picture/srcset`;
- режим отправки без изображений;
- двойная очистка HTML — в расширении и приложении TabTome;
- уменьшение и преобразование изображений для электронных книг;
- загрузка вставленных remote-изображений без cookies, redirects и доступа к literal private/local адресам;
- настройка отправителя и получателей Kindle/PocketBook без передачи SMTP-пароля расширению;
- выбор получателя перед отправкой, профиль по умолчанию и проверка домена `@pbsync.com`;
- проверяемый список первоначальной настройки;
- контекстная команда **Отправить на читалку**;
- адаптивный список вкладок, поиск, счётчик выбора, автоматическое название и сводка;
- собственная иконка расширения и клавиатурная навигация переключателя режимов.
- хранение SMTP-пароля только через Windows DPAPI и автоматическая миграция старого `SMTP_PASS` из `.env`.
- per-user Windows-установщик с закреплённым Node.js 24 LTS, отдельной программой настройки, обновлением без потери данных и автоматическим переносом старой ручной установки.
- общие TypeScript, HTML и CSS для Firefox и Chrome; отдельные манифесты и отдельные воспроизводимые каталоги сборки.
- единая русско-английская сборка расширения: автоматический язык браузера либо ручной выбор **Автоматически / Русский / English**; переведены popup, настройки, контекстное меню и статусы расширения.
- выбрана и установлена новая иконка расширения: открытая оранжевая книга без стрелки на тёмно-синем фоне; исходные концепты сохранены для истории.
- для следующей публичной версии исправлена декларация данных Native Messaging: добавлен `personallyIdentifyingInfo`, поскольку расширение передаёт приложению email-адреса; SMTP-пароль расширению недоступен.
- приватные окна отключены через `incognito: not_allowed`, чтобы их метаданные не попадали в восьмидневный журнал заданий.
- исходный архив расширения содержит собственный `package-lock.json` и воспроизводится через `npm ci` в отдельной системной временной папке без доступа к родительскому `node_modules`.
- страницы политики конфиденциальности на русском и английском опубликованы по постоянным HTTPS-адресам `https://tab-tome.netlify.app/ru/privacy/` и `https://tab-tome.netlify.app/en/privacy/`.
- двуязычные главные страницы и справка лендинга опубликованы на `https://tab-tome.netlify.app/`; английский README, тексты карточки AMO и три скриншота 1280×800 синхронизированы с публичным репозиторием `akakybzdynia-boop/tabtome`.
- опубликован GitHub pre-release `v0.12.0-unsigned-preview` с явно помеченным неподписанным установщиком и совпадающей контрольной суммой SHA-256; официального подписанного релиза пока нет.
- расширение опубликовано в Chrome Web Store; установщик регистрирует Native Messaging для Firefox и Chrome/Chromium, а публичные сборки используют точный Chrome origin.
- подготовлена инфраструктура Authenticode через SignPath: обычный Windows CI, ручной tag-only workflow, раздельная подпись внутренних EXE и установщика, проверка подписей, двуязычная политика и инструкция настройки. Заявка SignPath не подавалась, секреты GitHub не настраивались, подписанная сборка не создавалась.
- для Gmail добавлены готовые режимы STARTTLS 587 и TLS 465, а некорректные сочетания параметров отклоняются до сетевой проверки;
- зелёная галка на кнопке расширения сбрасывается через 15 секунд после успешной отправки.

## Проверено

- 9 файлов Vitest, 49 тестов;
- реальная миграция установленного пароля: `SMTP_PASS` удалён из `.env`, DPAPI-файл создан, SMTP-диагностика пройдена;
- TypeScript-проверка всех частей;
- контракт AMO-архива и windowless launcher;
- воспроизводимая сборка из плоского ZIP исходников;
- изолированный визуальный стенд: 25 вкладок, нулевой разброс левых координат, отсутствие горизонтального переполнения, проверки прокрутки обоих режимов и восстановление текстового черновика;
- отдельный сценарий реального Firefox Native Messaging с тестовым сообщением 20 МБ сохранён в проекте.
- настоящий EXE-установщик проверен в изолированном временном каталоге: миграция старых настроек, bundled runtime, manifest/реестр, Native Messaging launcher и полное удаление.
- статически проверены Chrome Manifest V3 service worker, API-совместимость, комплект файлов и отсутствие Firefox-only полей в Chrome package.
- статически проверены маршруты лендинга RU/EN, переключатели языка, политика конфиденциальности и размеры трёх PNG для AMO.

Headless UI-тест не запустился в установленном Firefox 153.0.4 из-за ошибки его графического backend `RenderCompositorSWGL failed mapping default framebuffer`; это сбой запуска тестового браузера до загрузки расширения, а не падение проверки интерфейса.

## Что остаётся перед эксплуатацией

- установить TabTome 0.12.1 из публичных карточек AMO и Chrome Web Store в чистые профили и проверить связь с приложением Windows 0.12.0;
- проверить реальную отправку и локальное сохранение нескольких вкладок с одной намеренно неподдерживаемой страницы и частичный результат;
- выполнить реальную отправку нескольких вкладок с одной намеренно неподдерживаемой страницей и проверить частичный результат.
- выполнить реальную доставку EPUB на адрес `@pbsync.com` и проверить появление книги на PocketBook после синхронизации.
- подать заявку на бесплатную подпись SignPath Foundation, настроить GitHub secret/variables и выполнить первый реальный tag-only workflow; до успешной проверки Authenticode установщик остаётся неподписанным и SmartScreen может показать «Неизвестный издатель».
- провести повторный end-to-end тест Chrome и Chromium после установки Windows-инсталлятора; Firefox для работы Chrome-сборки не требуется.

Инструкции находятся в `README.md`, модель угроз — в `SECURITY.md`, архитектурные решения — в `docs/adr`, изменения публичных версий расширения и приложения — в `docs/releases/v0.12.0.md` и `docs/releases/v0.12.1.md`.
