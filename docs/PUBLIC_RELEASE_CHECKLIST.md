## Подпись Windows-релиза

- каноническая политика: `CODE_SIGNING_POLICY.md`, перевод: `CODE_SIGNING_POLICY.ru.md`;
- настройка SignPath и GitHub: `docs/SIGNPATH_SETUP.md`;
- обычная проверка: `.github/workflows/windows-ci.yml`;
- ручная сборка кандидата с подписью: `.github/workflows/windows-signpath.yml`;
- workflow разрешает только тег `windows-v<версия приложения>`, не публикует GitHub Release и не имеет `contents: write`;
- после первого реального запуска проверить подписи внутренних EXE и установщика, SHA-256, чистую установку, обновление, Native Messaging, доставку EPUB и удаление;
- uninstaller Inno Setup в текущей схеме остаётся неподписанным — это известное ограничение.

## Compliance check

Статус: **можно продолжать с условиями**. Это рабочая проверка проекта, а не юридическое заключение.

- Mozilla считает данные, отправленные через Native Messaging, переданными за пределы расширения. Категории в манифесте должны оставаться синхронизированы с фактическим протоколом.
- Email-адреса относятся к personally identifying information. SMTP-пароль не относится к данным расширения, пока вводится только в Windows-приложении и не передаётся через Native Messaging.
- Содержимое уходит внешним организациям только по команде пользователя: SMTP-провайдеру и выбранному сервису Amazon или PocketBook.
- У разработчика нет backend, аналитики или телеметрии, поэтому он не получает содержимое книг и настройки пользователей.
- При добавлении аналитики, облачной синхронизации, собственного SMTP relay или поддержки приватных окон нужно заново пересмотреть манифест, согласие пользователя и политику конфиденциальности.
