# ADR 0006: Rich paste and extension icon

## Status

Accepted for version 0.8.0.

## Decision

The popup uses an explicitly focused `contenteditable` region instead of a textarea. Only user-initiated `paste` and `drop` events are read; the extension does not request `clipboardRead`. The client keeps a small semantic allowlist, removes styling and active elements, assigns opaque IDs to pasted images, and sends HTML plus image data to the background task.

The background converts clipboard and remote images through the existing image policy. The native host advertises `pastedRichText`, validates the payload and sanitizes the HTML again before EPUB generation. Text articles have no source link. The body and images are never written to extension storage or the job ledger.

The extension has an original page-and-arrow icon. Its source is deterministic SVG; the packaged PNG sizes are generated by `scripts/generate-icons.ps1`. The mark does not use Mozilla, Firefox, Amazon or Kindle trademarks.

## Compatibility

Native Messaging protocol remains version 1. Host 0.8.0 continues to accept legacy plain-text articles. Extension 0.8.0 can send tabs through an older host, but rich-text mode is disabled until `pastedRichText` is advertised. This prevents silent loss of formatting and images.

## Limits

- 1,000,000 visible text characters;
- 5 MB rich HTML;
- 30 images;
- 12 MB per source image and 15 MB source-image total;
- existing 4 MB normalized-image and 18 MB EPUB limits remain.
