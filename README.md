# TabTome

[English](README.en.md) · [Сайт](https://tabtome.netlify.app/ru/) · [Политика конфиденциальности](https://tabtome.netlify.app/ru/privacy/)

Локальная система для Windows: расширение браузера извлекает статьи из уже открытых вкладок через Mozilla Readability либо принимает вставленный пользователем форматированный текст и изображения. Приложение TabTome запускается по требованию, собирает EPUB и отправляет его на Kindle или PocketBook через SMTP. Рабочая установка сейчас рассчитана на Firefox; из той же кодовой базы также собирается Chrome-пакет, для которого ещё не добавлена регистрация приложения.

Текущая подготовленная версия расширения и приложения для Windows — 0.11.1. Они используют Native Messaging protocol 2 и поддерживают локальные профили Kindle и PocketBook. SMTP-пароль допускается только в защищённом Windows DPAPI-файле; найденный при обновлении `SMTP_PASS` автоматически переносится из `.env` и удаляется оттуда после проверки. Постоянного HTTP-сервера, порта 3210, токена, watchdog и автозапуска при входе в Windows нет. Firefox сам запускает приложение на время проверки или отправки и завершает его после закрытия соединения.

Исходный код проекта распространяется по [Mozilla Public License 2.0](LICENSE). Изменённые файлы исходного кода должны оставаться под MPL-2.0; проект можно объединять с кодом под другими совместимыми условиями. Сторонние зависимости сохраняют собственные лицензии.

## Возможности и ограничения

- одна или до 25 вкладок в одной EPUB-книге;
- продолжение подготовки книги, если часть выбранных вкладок не удалось обработать, с отдельным результатом для каждой вкладки;
- отдельный режим для вставки текста объёмом до 1 000 000 символов;
- временное восстановление незавершённого текста из памяти текущего сеанса Firefox;
- ручная вставка через `Ctrl+V` без разрешения `clipboardRead`;
- сохраняются абзацы, заголовки, выделение, списки, цитаты, код, ссылки, таблицы и изображения; шрифты, цвета, стили и активное содержимое удаляются;
- содержимое берётся из уже открытой страницы, поэтому работают авторизация и отрисованный JavaScript;
- до 30 изображений на статью и до 15 МБ изображений на отправку;
- режим **Без изображений**, который сохраняет текст, ссылки и структуру, но не загружает изображения;
- команда контекстного меню **Отправить на читалку** для текущей страницы или выделенного текста;
- настройка адресов отправителя, Kindle и PocketBook из Firefox; SMTP-пароль расширению не передаётся;
- выбор Kindle или PocketBook перед отправкой; адрес PocketBook ограничен доменом `@pbsync.com`;
- WebP, AVIF и SVG преобразуются в JPEG либо PNG; GIF сохраняется;
- изображения ограничиваются рамкой 1280×1680, grayscale JPEG q80 включён по умолчанию;
- EPUB больше 18 МБ отклоняется до SMTP;
- HTML повторно очищается в приложении TabTome;
- результат отправки сохраняется на диске восемь дней и защищается от дублей по `jobId`;
- страницы `about:`, встроенные PDF и страницы магазина дополнений Firefox извлечь нельзя;
- видео, формы и исходные стили страницы в EPUB не переносятся.

## Установка на Windows

Нужны 64-разрядная Windows 10 версии 1809 или новее и Firefox 142+. Отдельно устанавливать Node.js, npm или запускать PowerShell не требуется.

1. Запустите `TabTome-Setup-0.11.1.exe` обычным пользователем. Новая установка размещается без прав администратора в `%LOCALAPPDATA%\Programs\TabTome` и регистрирует Native Messaging host только в `HKCU`.

2. На последнем экране откройте программу настройки. Укажите адрес отправителя, адрес Kindle и/или PocketBook, получателя по умолчанию и пароль приложения SMTP. Для Gmail используются `smtp.gmail.com`, порт `587`, выключенный прямой TLS и отдельный 16-значный пароль приложения Google. Пароль шифруется Windows DPAPI; открытая копия на диске не создаётся.

3. Для Kindle добавьте отправителя в список разрешённых адресов Amazon. Для PocketBook добавьте его в белый список Send-to-PocketBook. Подтвердите только настроенные сервисы и нажмите **Сохранить и проверить SMTP**.

4. После одобрения Mozilla установите подписанное расширение Firefox 0.11.1 и полностью перезапустите Firefox. В настройках расширения список готовности должен стать зелёным. Затем один раз нажмите **Проверить канал 20 МБ**: тест проходит через настоящий механизм Firefox, но не создаёт EPUB и не отправляет письмо.

5. Для страниц выберите режим **Вкладки**, отметьте одну или несколько вкладок и нажмите **Отправить выбранное**. Для произвольного содержимого выберите **Текст**, вставьте текст или изображения через `Ctrl+V` и нажмите **Отправить текст**.

Установщик включает закреплённый Node.js 24 LTS. Код приложения обновляется отдельно от пользовательских данных:

```text
%LOCALAPPDATA%\Programs\TabTome             — программа и встроенный runtime при чистой установке
%LOCALAPPDATA%\PageToEreaderLocal           — настройки, DPAPI-пароль, задания и журналы
```

При обновлении Inno Setup может сохранить прежний каталог программы. Это нормально: `AppId`, каталог данных и Native Messaging ID не менялись, чтобы обновление не создавало вторую установку и не теряло настройки.

Если раньше компонент был зарегистрирован из распакованной папки проекта, установщик автоматически переносит `.env`, `.smtp-pass` и `data\settings.json` из прежней папки `server`. Исходная папка не удаляется.

## Обновление и удаление

Перед обновлением дождитесь окончания текущей отправки и запустите новый `TabTome-Setup-*.exe`. Постоянный `AppId` обновляет существующую установку, а данные в `%LOCALAPPDATA%\PageToEreaderLocal` не перезаписываются. Этот путь данных и внутренние Native Messaging ID намеренно сохраняют прежние имена для совместимости.

Удаление доступно в меню «Пуск» и в разделе «Установленные приложения» Windows. Удаляется программа и регистрация Firefox. Отдельный вопрос позволяет либо сохранить SMTP-настройки и историю для переустановки, либо удалить их без возможности восстановления.

Старый ручной сценарий `install-native-host.ps1` оставлен только для разработки и восстановления. Для обычной установки он больше не нужен.

## Диагностика

Проверить настройки, хранилище заданий и соединение с SMTP без Firefox:

```powershell
powershell.exe -ExecutionPolicy Bypass -File .\run-diagnostics.ps1
```

Ожидаемый результат заканчивается строками `SMTP connection: OK` и `Native host is ready.` Журнал установленной версии: `%LOCALAPPDATA%\PageToEreaderLocal\logs\service.log`; при 5 МБ он ротируется в `service.previous.log`. Открыть настройки и журнал можно через ярлык **TabTome** в меню «Пуск».

Полностью автоматическая проверка 20-МБ сообщения в отдельном временном профиле Firefox:

```powershell
powershell.exe -ExecutionPolicy Bypass -File .\test-firefox-native-load.ps1
```

Проверка выравнивания popup и очистки форматированной вставки в настоящем headless Firefox:

```powershell
powershell.exe -ExecutionPolicy Bypass -File .\test-firefox-popup.ps1
```

Сценарий временно подставляет тестовый Native Messaging manifest, загружает неподписанное расширение через WebDriver BiDi, передаёт 20 МБ, закрывает Firefox и в `finally` восстанавливает прежнее значение реестра. Рабочий профиль Firefox не используется.

Если расширение пишет, что приложение TabTome не найдено:

- повторно запустите актуальный `TabTome-Setup-*.exe`;
- полностью закройте все окна Firefox и откройте браузер снова;
- откройте **TabTome** из меню «Пуск» и запустите диагностику;
- для ручной установки из исходников проверьте ID `page-to-ereader-local@local` и повторно запустите `install-native-host.ps1`.

Ручное удаление регистрации разработки:

```powershell
powershell.exe -ExecutionPolicy Bypass -File .\uninstall-native-host.ps1
```

Этот скрипт не относится к установленной EXE-версии и не удаляет файлы проекта.

## Отправка расширения в Mozilla Add-ons

Архив дополнения должен содержать только файлы из `extension\dist`, причём `manifest.json` должен находиться в корне ZIP. Не добавляйте `server`, `host`, `node_modules`, `.env` или весь проект.

На вопрос о генераторах и объединении кода отвечайте **Да**: сборка использует esbuild и объединяет Mozilla Readability с content script. Отдельно приложите исходный архив расширения. В описании разрешения `nativeMessaging` укажите, что оно запускает установленное пользователем приложение TabTome для сборки EPUB и отправки на настроенный адрес Kindle или PocketBook.

## Chrome-сборка

Обе сборки используют общие `extension\src`, HTML, CSS, Readability и иконки:

```powershell
npm.cmd run build:firefox -w extension
npm.cmd run build:chrome -w extension
```

Firefox создаётся в `extension\dist`, Chrome — в `extension\dist-chrome`. Полная команда `npm.cmd run build -w extension` создаёт обе папки. Для локальной проверки интерфейса Chrome откройте `chrome://extensions`, включите режим разработчика, нажмите **Load unpacked / Загрузить распакованное расширение** и выберите папку `extension\dist-chrome`.

Chrome-сборка требует Chrome 127+ из-за программного открытия popup после команды контекстного меню. Она использует Manifest V3 service worker и не содержит Firefox-only полей `browser_specific_settings` и `data_collection_permissions`.

Ограничение текущего этапа: существующий Windows-установщик регистрирует Native Messaging только для Firefox. Chrome требует отдельный host manifest с точным `chrome-extension://<ID>/`; wildcard запрещён. Поэтому до получения стабильного ID из Chrome Web Store кнопки и интерфейс можно проверить, но отправка завершится сообщением об отсутствующем локальном приложении. Следующий отдельный шаг — добавить этот ID в установщик и провести end-to-end тест в Chrome.

## Разработка и проверка

```powershell
npm.cmd run build
npm.cmd test
```

Сборка и изолированная проверка Windows-установщика описаны в `docs/WINDOWS_INSTALLER.md`.

`npm.cmd test` также проверяет, что launcher имеет Windows GUI-subsystem, не создаёт консоль и не загрязняет stdout. Системные Firefox-тесты запускаются отдельно: проверка Native Messaging временно пишет в HKCU, а UI-тест создаёт только временный профиль и локальные тестовые страницы.

Firefox-сборка находится в `extension\dist`, Chrome-сборка — в `extension\dist-chrome`. Для временной установки Firefox откройте `about:debugging` → **Этот Firefox** → **Загрузить временное дополнение** и выберите `extension\dist\manifest.json`. Native host всё равно должен быть зарегистрирован установщиком, а его разрешённый ID должен совпадать с ID расширения.

Архитектурные решения находятся в `docs\adr`; модель угроз — в `SECURITY.md`. Политика подписи Windows-релизов: `CODE_SIGNING_POLICY.ru.md` (английская каноническая версия — `CODE_SIGNING_POLICY.md`). Подготовка SignPath описана в `docs\SIGNPATH_SETUP.md`; workflow подписи не работает до одобрения заявки и настройки секретов GitHub и не публикует GitHub Release автоматически.
