# Page to E-reader Local 0.8.0

Локальная система для Windows: расширение Firefox извлекает статьи из уже открытых вкладок через Mozilla Readability либо принимает вставленный пользователем форматированный текст и изображения. Запускаемый по требованию Node.js-компонент собирает EPUB и отправляет его на Kindle через SMTP.

В версии 0.8.0 сохраняется Native Messaging protocol 1 и добавляется capability `pastedRichText`. Постоянного HTTP-сервера, порта 3210, токена, watchdog и автозапуска при входе в Windows нет. Firefox сам запускает локальный компонент на время проверки или отправки и завершает его после закрытия соединения. Оконный launcher запускает Node.js без консоли и прозрачно передаёт бинарный протокол.

## Возможности и ограничения

- одна или до 25 вкладок в одной EPUB-книге;
- отдельный режим для вставки текста объёмом до 1 000 000 символов;
- ручная вставка через `Ctrl+V` без разрешения `clipboardRead`;
- сохраняются абзацы, заголовки, выделение, списки, цитаты, код, ссылки, таблицы и изображения; шрифты, цвета, стили и активное содержимое удаляются;
- содержимое берётся из уже открытой страницы, поэтому работают авторизация и отрисованный JavaScript;
- до 30 изображений на статью и до 15 МБ изображений на отправку;
- WebP, AVIF и SVG преобразуются в JPEG либо PNG; GIF сохраняется;
- изображения ограничиваются рамкой 1280×1680, grayscale JPEG q80 включён по умолчанию;
- EPUB больше 18 МБ отклоняется до SMTP;
- HTML повторно очищается в локальном компоненте;
- результат отправки сохраняется на диске восемь дней и защищается от дублей по `jobId`;
- страницы `about:`, встроенные PDF и страницы магазина дополнений Firefox извлечь нельзя;
- видео, формы и исходные стили страницы в EPUB не переносятся.

## Чистая установка на Windows

Нужны Node.js 20+ и Firefox 142+.

1. Распакуйте полный архив в постоянную папку. После регистрации эту папку нельзя переносить без повторного запуска установщика.

2. В корне проекта установите зависимости и соберите оба компонента:

   ```powershell
   npm.cmd install
   npm.cmd run build
   ```

3. Создайте настройки SMTP:

   ```powershell
   Copy-Item server\.env.example server\.env
   notepad server\.env
   ```

   Для Gmail обычно используются `smtp.gmail.com`, порт `587`, `SMTP_SECURE=false` и 16-значный пароль приложения Google. Адрес `SMTP_FROM` добавьте в Amazon в список разрешённых отправителей документов.

4. Необязательно, но рекомендуется: защитите SMTP-пароль средствами Windows DPAPI:

   ```powershell
   powershell.exe -ExecutionPolicy Bypass -File .\protect-smtp-password.ps1
   ```

   После успешного создания `server\.smtp-pass` удалите строку `SMTP_PASS=...` из `server\.env`. Защищённый файл работает только у создавшего его пользователя Windows.

5. Зарегистрируйте локальный компонент для текущего пользователя Windows — права администратора не нужны:

   ```powershell
   powershell.exe -ExecutionPolicy Bypass -File .\install-native-host.ps1
   ```

   Установщик штатным компилятором Windows собирает `host\PageToEreaderHost.exe` с GUI-subsystem, записывает точный путь к `node.exe`, создаёт Native Messaging manifest без BOM и регистрирует его в HKCU. Поэтому окно командной строки при проверках и отправках не появляется.

6. Установите подписанное расширение 0.8.0. Новых разрешений по сравнению с 0.7.0 нет; доступ к системному буферу обмена расширение не запрашивает.

7. Полностью перезапустите Firefox. Откройте значок расширения → **Настройки** → **Сохранить и проверить**. Должно появиться сообщение, что локальный компонент и SMTP работают. Затем один раз нажмите **Проверить канал 20 МБ**: тест проходит через настоящий механизм Firefox, но не создаёт EPUB и не отправляет письмо.

8. Для страниц выберите режим **Вкладки**, отметьте одну или несколько вкладок и нажмите **Отправить выбранное**. Для произвольного содержимого выберите **Текст**, вставьте текст или изображения через `Ctrl+V`, при необходимости задайте название и нажмите **Отправить текст**. Всплывающее окно можно закрыть: открытое Native Messaging-соединение удерживает фоновую операцию до результата.

## Обновление с 0.6.x или 0.7.x

Сначала дождитесь окончания текущей отправки.

1. Сделайте резервную копию `server\.env` и `server\.smtp-pass`, если он существует.

2. Распакуйте полный архив 0.8.0 поверх прежней папки. Если проект когда-либо обновлялся с версии 0.5.x, не пропускайте последующий запуск `install-native-host.ps1`: установщик удалит оставшиеся от HTTP-сервера файлы `app.ts`, `auth.ts` и `index.ts` перед сборкой. В дальнейших версиях используйте `update-project.ps1`, который также удаляет известные устаревшие файлы и сохраняет SMTP-настройки.

3. Обновите зависимости, соберите проект и повторно зарегистрируйте Native Messaging host:

   ```powershell
   npm.cmd install
   powershell.exe -ExecutionPolicy Bypass -File .\install-native-host.ps1
   ```

   `install-native-host.ps1` сам выполняет чистую сборку серверной части и не меняет регистрацию, если TypeScript сообщает об ошибке. Отдельная команда `npm.cmd run build` при обновлении не требуется.

4. Установите подписанное расширение 0.8.0 и полностью перезапустите Firefox. Затем запустите проверку в настройках расширения. Пока установлен host 0.7.x, отправка вкладок продолжает работать, но режим форматированного текста требует host 0.8.0.

Старый архив сохраните до успешной отправки вкладки и вставленного текста.

## Диагностика

Проверить настройки, хранилище заданий и соединение с SMTP без Firefox:

```powershell
powershell.exe -ExecutionPolicy Bypass -File .\run-diagnostics.ps1
```

Ожидаемый результат заканчивается строками `SMTP connection: OK` и `Native host is ready.` Журнал ошибок: `server\logs\service.log`; при 5 МБ он ротируется в `service.previous.log`.

Полностью автоматическая проверка 20-МБ сообщения в отдельном временном профиле Firefox:

```powershell
powershell.exe -ExecutionPolicy Bypass -File .\test-firefox-native-load.ps1
```

Проверка выравнивания popup и очистки форматированной вставки в настоящем headless Firefox:

```powershell
powershell.exe -ExecutionPolicy Bypass -File .\test-firefox-popup.ps1
```

Сценарий временно подставляет тестовый Native Messaging manifest, загружает неподписанное расширение через WebDriver BiDi, передаёт 20 МБ, закрывает Firefox и в `finally` восстанавливает прежнее значение реестра. Рабочий профиль Firefox не используется.

Если расширение пишет, что компонент не найден:

- повторно запустите `install-native-host.ps1`;
- убедитесь, что папку проекта после установки не переносили;
- полностью закройте все окна Firefox и откройте браузер снова;
- проверьте, что расширение имеет ID `page-to-ereader-local@local`;
- запустите `run-diagnostics.ps1` и посмотрите журнал.

Удаление регистрации:

```powershell
powershell.exe -ExecutionPolicy Bypass -File .\uninstall-native-host.ps1
```

Файлы проекта, SMTP-настройки, история заданий и журналы при этом не удаляются.

## Отправка расширения в Mozilla Add-ons

Архив дополнения должен содержать только файлы из `extension\dist`, причём `manifest.json` должен находиться в корне ZIP. Не добавляйте `server`, `host`, `node_modules`, `.env` или весь проект.

На вопрос о генераторах и объединении кода отвечайте **Да**: сборка использует esbuild и объединяет Mozilla Readability с content script. Отдельно приложите исходный архив расширения. В описании разрешения `nativeMessaging` укажите, что оно запускает установленный пользователем локальный компонент для сборки EPUB и отправки на его адрес Kindle.

## Разработка и проверка

```powershell
npm.cmd run build
npm.cmd test
```

`npm.cmd test` также проверяет, что launcher имеет Windows GUI-subsystem, не создаёт консоль и не загрязняет stdout. Системные Firefox-тесты запускаются отдельно: проверка Native Messaging временно пишет в HKCU, а UI-тест создаёт только временный профиль и локальные тестовые страницы.

Сборка расширения находится в `extension\dist`. Для временной установки откройте `about:debugging` → **Этот Firefox** → **Загрузить временное дополнение** и выберите `extension\dist\manifest.json`. Native host всё равно должен быть зарегистрирован установщиком, а его `allowed_extensions` должен совпадать с ID дополнения.

Архитектурные решения находятся в `docs\adr`; модель угроз — в `SECURITY.md`.
